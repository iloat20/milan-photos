# F2: Photography wall / artwork grid layouts — justified vs masonry vs fixed-aspect grids, and equal-height-row trade-offs for a physical "hung on a wall" metaphor

## Findings

### [1] Flickr's production justified-layout algorithm treats row height as a soft target (default 320px, ±25% tolerance) and scales each image's width to fit that row without cropping.
- quote: "It's called a target because row height is the lever we use in order to fit everything in nicely. The algorithm will get as close to the target row height as it can."
- url: http://flickr.github.io/justified-layout/
- source_type: primary
- published: unknown (npm package `justified-layout`; docs live)
- confidence: high

### [2] True justified rows require per-row width adjustment by aspect ratio; forcing a single aspect ratio (`forceAspectRatio`) deliberately discards natural image proportions while keeping item count.
- quote: "Provide an aspect ratio here to return everything in that aspect ratio. Makes the values in your input array irrelevant. The length of the array remains relevant."
- url: http://flickr.github.io/justified-layout/
- source_type: primary
- published: unknown
- confidence: high

### [3] Incomplete last rows ("widows") are an explicit design decision in justified layouts — Flickr defaults to showing them; omitting them (`showWidows: false`) leaves a ragged wall unless handled another way.
- quote: "By default we'll return items at the end of a justified layout even if they don't make a full row. If `false` they'll be omitted from the output."
- url: http://flickr.github.io/justified-layout/
- source_type: primary
- published: unknown
- confidence: high

### [4] Industry justified galleries frame the layout as a brick-wall metaphor used by 500px, Flickr, and Google — i.e. dense equal-height rows, not museum salon hang.
- quote: "Important websites such as 500px, Flickr, or Google display images in an excellent way, justifying them similarly to brick wall."
- url: https://miromannino.github.io/Justified-Gallery/
- source_type: primary
- published: unknown (Justified Gallery 4.x docs; 500px cited as adopter)
- confidence: high

### [5] Justified Gallery's core value claim is no crop / no distortion: rows fill container width by scaling, not by `object-fit: cover` clipping — unlike fixed-aspect grids that must letterbox or crop.
- quote: "An advanced justification algorithm sizes every row to fill the available width without ever cropping or distorting your images."
- url: https://miromannino.github.io/Justified-Gallery/
- source_type: primary
- published: unknown
- confidence: high

### [6] Equal-height justified libraries still expose last-row policy knobs (`lastRow: nojustify|justify|hide|left|center|right`) because exact-width justification of a short final row is usually undesirable for photo walls.
- quote: "Decide to justify the last row (using `'justify'`) or not (using `'nojustify'`), or to hide the row if it can't be justified (using `'hide'`)."
- url: https://miromannino.github.io/Justified-Gallery/options-and-events/
- source_type: primary
- published: unknown
- confidence: high

### [7] Capping max row height in a justified gallery can crop images — a documented trade-off when chasing tighter wall rows at the expense of full artwork visibility.
- quote: "Note that this option can crop the images if they need to be taller to be justified."
- url: https://miromannino.github.io/Justified-Gallery/options-and-events/
- source_type: primary
- published: unknown
- confidence: high

### [8] CSS masonry / grid-lanes (`display: grid-lanes`) is still experimental as of MDN (page last modified 2026-08-27) and is not Baseline — pure-CSS waterfall cannot be assumed production-safe for a GitHub Pages audience in 2026.
- quote: "This feature is not Baseline because it does not work in some of the most widely-used browsers."
- url: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Grid_lanes
- source_type: primary
- published: 2026-08-27
- confidence: high

### [9] W3C CSS Grid Level 3 defines grid-lanes auto-placement as packing each item into the shortest track (Pinterest-style column packing), which yields unequal row bottoms — opposite of equal-height justified rows used for "hung" paintings.
- quote: "Grid lanes layout, sometimes also called “masonry layout” or “waterfall layout” … each item is placed into the column with the smallest height so far."
- url: https://drafts.csswg.org/css-grid-3/
- source_type: primary
- published: 2026-09-02 (Editor's Draft)
- confidence: high

### [10] Masonry/grid-lanes can break visual reading order when spans or mixed heights cause backtracking; the spec warns authors to minimize this for focus/keyboard order — a real cost vs sequential equal-height rows.
- quote: "Authors should be aware of these possibilities and design layouts where such backtracking is minimized so that focus and reading order can be more easily followed."
- url: https://drafts.csswg.org/css-grid-3/
- source_type: primary
- published: 2026-09-02
- confidence: high

### [11] The CSS Grid L3 spec itself names a horizontal "brick wall style" mode (`grid-template-rows` + grid-lanes) as the wall-metaphor orientation — conceptually closer to a gallery hang than vertical Pinterest columns.
- quote: "the following code will make a 2-row (“brick wall style”) grid lanes container that grows horizontally"
- url: https://drafts.csswg.org/css-grid-3/
- source_type: primary
- published: 2026-09-02
- confidence: high

### [12] Fixed-aspect gallery cells need explicit crop/letterbox policy: `object-fit: cover` clips content to fill the frame; `contain` letterboxes — so equal-cell "picture frame" grids trade full-artwork fidelity for wall regularity.
- quote: "If the object's aspect ratio does not match the aspect ratio of its box, then the object will be clipped to fit." (cover)
- url: https://developer.mozilla.org/en-US/docs/Web/CSS/object-fit
- source_type: primary
- published: 2026-07-21
- confidence: high

### [13] CSS `aspect-ratio` (Baseline since ~Sep 2021) is the modern way to force fixed-aspect frame boxes on a grid wall; at least one box dimension must be automatic for the ratio to take effect.
- quote: "At least one of the box's sizes needs to be automatic in order for aspect-ratio to have any effect."
- url: https://developer.mozilla.org/en-US/docs/Web/CSS/aspect-ratio
- source_type: primary
- published: 2026-07-21
- confidence: high

### [14] Photo wall lightboxes (PhotoSwipe 5.4.4) require predefined width/height per image and mark cropped thumbnails explicitly — justified/fixed-aspect list layouts must carry dimensions into the lightbox or transitions and zoom break.
- quote: "PhotoSwipe requires predefined image dimensions, you must define the width and height of each image."
- url: https://photoswipe.com/getting-started/
- source_type: primary
- published: unknown (v5.4.4 current docs; v6 in development)
- confidence: high

### [15] Dense multi-image galleries are layout-shift sensitive: a ~100-image gallery measured 75–450ms layout with dimensions vs 124–2709ms without — justified/custom layouts that omit intrinsic sizes punish scroll performance on a photo wall.
- quote: "Chrome Dev tools showing various layout timings of 75ms to 450ms on the left, and 124ms to 2709ms on the right" (gallery of about 100 images)
- url: https://www.smashingmagazine.com/2020/03/setting-height-width-images-important-again/
- source_type: secondary
- published: 2020-03 (updated 2022-01-11)
- confidence: high
