# F4: Photo browsing interaction and performance baselines — lightboxes, carousels, lazy loading, responsive WebP/srcset, View Transitions, SW offline media, and a11y (incl. prefers-reduced-motion) on high-quality photography sites

## Findings

### [1] Lightboxes should follow the W3C APG modal-dialog baseline: role=dialog + aria-modal=true, focus moves in on open, Tab is trapped inside, Escape closes, and focus returns to the invoker.
- quote: "When a dialog opens, focus moves to an element inside the dialog… Tab: Moves focus to the next tabbable element inside the dialog… Escape: Closes the dialog… When a dialog closes, focus returns to the element that invoked the dialog"
- url: https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
- source_type: primary
- published: unknown (living APG; W3C WAI)
- confidence: high

### [2] APG further requires that modal lightboxes only set aria-modal when both interaction-blocking and visual obscuring are real; partial modality is worse than none for AT users.
- quote: "mark a dialog modal only when both: 1. Application code prevents all users from interacting in any way with content outside of it. 2. Visual styling obscures the content outside of it."
- url: https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
- source_type: primary
- published: unknown (living APG; W3C WAI)
- confidence: high

### [3] Hero/image carousels must expose explicit rotation control and auto-stop on focus/hover; slides need aria-roledescription="slide" and accessible names (e.g. "3 of 10").
- quote: "If the carousel can automatically rotate, it also: Has a button for stopping and restarting rotation… Stops rotating when keyboard focus enters the carousel… Stops rotating whenever the mouse is hovering over the carousel."
- url: https://www.w3.org/WAI/ARIA/apg/patterns/carousel/
- source_type: primary
- published: unknown (living APG; W3C WAI)
- confidence: high

### [4] WCAG 2.2 SC 2.3.3 (Animation from Interactions, Level AAA) requires non-essential interaction-triggered motion to be disableable; the named sufficient techniques are CSS prefers-reduced-motion and the same query in JS.
- quote: "Motion animation triggered by interaction can be disabled, unless the animation is essential… C39: Using the CSS prefers-reduced-motion query to prevent motion… SCR40: Using the CSS prefers-reduced-motion query in JavaScript to prevent motion"
- url: https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html
- source_type: primary
- published: 2025-09-16 (page updated)
- confidence: high

### [5] prefers-reduced-motion is Baseline widely available since January 2020; scaling/panning large objects (lightbox open/zoom, full-bleed carousel pans) are the named vestibular triggers to tone down to opacity-only transitions.
- quote: "This feature is well established… available across browsers since January 2020… Animations such as scaling or panning large objects can be vestibular motion triggers."
- url: https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion
- source_type: primary
- published: 2026-06-10 (last modified)
- confidence: high

### [6] Native lazy-loading is the baseline for photo walls, but lazy images must carry explicit width/height (or aspect-ratio) or CLS gets worse; loading is deferred only when JS is enabled (anti-tracking).
- quote: "While explicit width and height attributes are recommended for all images to avoid layout shift, they are especially important for lazy-loaded ones… Loading is only deferred when JavaScript is enabled. This is an anti-tracking measure"
- url: https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img
- source_type: primary
- published: 2026-09-11 (last modified)
- confidence: high

### [7] Responsive photo delivery uses srcset+sizes for resolution switching and <picture>+media for art direction; MDN's worked example saves ~65KB (128KB→63KB) per image on a narrow viewport — meaningful when multiplied across a justified gallery.
- quote: "The 800px picture is 128KB on disk, whereas the 480px version is only 63KB — a saving of 65KB. Now, imagine if this was a page that had many pictures on it."
- url: https://developer.mozilla.org/en-US/docs/Web/HTML/Guides/Responsive_images
- source_type: primary
- published: 2025-11-06 (last modified)
- confidence: high

### [8] WebP is the current format baseline for photography: lossy WebP is on average 25–35% smaller than visually similar JPEG; lossless WebP is typically ~26% smaller than PNG; AVIF often compresses further (~50% vs JPEG) but needs <picture> fallbacks and does not progressive-render.
- quote: "Lossy WebP images are on average 25–35% smaller than JPEG images of visually similar compression levels. Lossless WebP images are typically 26% smaller than the same images in PNG format."
- url: https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types
- source_type: primary
- published: unknown (living MDN guide)
- confidence: high

### [9] View Transitions are MDN's own canonical SPA gallery pattern: document.startViewTransition() around the image swap yields a default cross-fade; without support the same DOM update still runs (progressive enhancement). Specs: CSS View Transitions L1/L2; gallery demos exist on mdn.github.io and view-transitions.chrome.dev.
- quote: "Basic View Transitions SPA demo: A basic image gallery demo with view transitions, featuring separate animations between old and new images, and old and new captions."
- url: https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API
- source_type: primary
- published: 2026-06-19 (last modified)
- confidence: high

### [10] For lightbox open/close with View Transitions, assign unique view-transition-name to the thumb and lightbox image; duplicate names cause ViewTransition.ready to reject and the transition is skipped — names must be cleared after snapshots (especially with bfcache).
- quote: "The value of view-transition-name for each rendered element must be unique. If two rendered elements have the same view-transition-name at the same time, ViewTransition.ready will reject and the transition will be skipped."
- url: https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API/Using
- source_type: primary
- published: 2026-09-15 (last modified)
- confidence: high

### [11] Service-worker offline media baseline: cache-first (or cache-first + network fill) via Cache API in install/fetch; new SW versions open a new named cache and delete old caches on activate — version-bumping the SW script is mandatory for updates to take effect.
- quote: "Inside addResourcesToCache() we use the caches.open() method to create a new cache called v1… we'll create a new cache in its install event handler… the activate event to remove data from the previous caches."
- url: https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers
- source_type: primary
- published: 2026-05-29 (last modified)
- confidence: high

### [12] Industry lightbox baseline (PhotoSwipe v5.4.4 docs): require predefined image dimensions on each link (data-pswp-width/height), recommend responsive sources (data-pswp-srcset) with max recommended size 3000×3000px, dynamically import lightbox Core only on open, and always provide a non-JS fallback link to the image.
- quote: "PhotoSwipe requires predefined image dimensions, you must define the width and height of each image… Maximum recommended size is 3000x3000px… Always provide an alternative way to view the content (for example, link to the image)."
- url: https://photoswipe.com/getting-started/
- source_type: secondary
- published: unknown (PhotoSwipe 5.4.4 docs; v6 in development)
- confidence: high

### [13] CSS scroll-snap (scroll-snap-type / scroll-snap-align / scroll-snap-stop, plus scrollsnapchange events) is the platform baseline for full-bleed hero carousels and swipeable lightbox sequences — touch paging without custom gesture JS.
- quote: "The CSS scroll snap module provides properties that let you control the panning and scrolling behavior by defining snap positions… providing paging and scroll positioning."
- url: https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_scroll_snap
- source_type: primary
- published: 2026-08-21 (last modified)
- confidence: high
