# 灯箱「点击 / 缩放」手势重设计（2026-09-26）

> 经 brainstorming 流程确认。范围：修 `灯箱双击缩放只能进不能出` 与 `手慢双击跳过两张`。
> 不在范围：双击时的画面闪烁（用户已明确排除 —— 消除它需要改成延迟切图，会让 1× 态单击手感倒退）。

## 1. 问题与既有证据

现象一（**双击只能进不能出**）：

```
双击前 zoom=1.6430 → 双击后 zoom=2.5；同一张画=true
```

根因：`click` 处理器**每次先** `step(±1)`，而 `step → sync → resetZoom(false)` 必然把 `zoom` 打回 1。于是 `toggleLbZoomAt` 里 `if (zoom > 1) { resetZoom(false); return; }` 这半边**永远不可达**。触屏用户双击放大后无法双击缩回，出路只有双指捏合或关闭重开。

现象二（**手慢双击跳过两张**）：

`tapTimer` 的固定 450ms 与浏览器双击判定窗口**不对齐**（Windows 系统可设 200–900ms，默认 500ms）。当用户双击间隔落在「>450ms 但浏览器仍判为双击」的区间：

```
click#1 (t=0)     无 tapTimer → step(1) 前进 1 张，起 450ms 计时
click#2 (t=600)   tapTimer 已过期 → 又 step(1) 前进 1 张        ← 共 2 张
dblclick (t=610)  清计时器 → 放大 2.5×
```

两者**同根**：都源于「用固定时长计时器模拟浏览器的双击判定」。

## 2. 设计意图的既有线索

`styles.css` 早已声明指针语义：

| 选择器 | 声明 | 语义 |
|---|---|---|
| `.lightbox-img` | `cursor: pointer` | 1× 态：点了 = 切图 |
| `.lightbox-img.is-zoomed` | `cursor: zoom-out` | 放大态：点了 = **缩小** |

`zoom-out` 是浏览器原生「单击缩小」的语义 —— 即**设计意图本就是「放大态单击缩回」**，那个不可达的 `if (zoom > 1)` 分支正是为它写的。因此本次不新增交互概念，而是**把已声明的意图实现出来**。

## 3. 被否决的方案

### 3.1 `e.detail`（浏览器原生连击计数）— 否决

实测结果：

| 场景 | 事件序列 |
|---|---|
| `mouse.dblclick()` | `click#1, click#2, dblclick#2` |
| 两次 `mouse.click` 间隔 200ms | `click#1, click#1` |
| 两次 `mouse.click` 间隔 600ms | `click#1, click#1` |
| 快速连点 4 次 | `#1, #1, #1, #1` |
| 触屏 `tap×2`（间隔 90ms） | `click#1, click#2, dblclick#2` |

决定性对比是第 1、2 行：**两者间隔都落在「浏览器应判双击」的范围**（3ms vs 200ms），但只有 `dblclick()` 给出 `detail=2`。差别不在时间，而在 Playwright 的 API —— `dblclick()` 显式传 `clickCount: 2`，`click()` 传 `1`。即那几行反映的是**合成输入的参数**，不是浏览器的连击判定。

结论：`e.detail` 在本仓库**无法被真实验证**（值由 API 决定而非时序），而 e2e 是唯一的交互回归网。基于它的逻辑写出来**不可测**，将来改坏了也不会红。

### 3.2 延迟切图（单击等 ~300ms 确认非双击再切）— 否决

能一次消除闪烁与全部连击判定，但代价是 **1× 态每次单击切图都有 300ms 可感知延迟** —— 连续翻 10 张即累积数秒。用户明确排除。

### 3.3 单纯拉长 450ms 窗口 — 否决

无法覆盖系统双击窗口上界（900ms），且窗口越长，「快速连点翻页」被合并的区间越大。治标。

## 4. 采用方案：`dblclick` 权威裁决 + 组起点绝对回退

不再猜「这是不是双击」，而是**由浏览器的 `dblclick` 事件做权威裁决**；我们只负责记住「这一组点击从哪个位置开始」。回退目标是**绝对位置**而不是相对步数。

```
GROUP_MS = 1000

click:
  if (didSwipe) { didSwipe = false; return }        // 拖拽后的合成 click，吞掉
  sameGroup = now - groupAt < GROUP_MS ;  groupAt = now
  if (zoom > 1) {                                   // ① 放大态：本击 = 缩回
    if (!sameGroup) { kind = "out"; groupStart = pos }
    resetZoom(false); return
  }
  if (!sameGroup) { kind = "adv"; groupStart = pos }
  else if (kind === "out") return                   // 缩回组的余波，吞掉
  step(1)                                           // ② 1× 态：乐观切图（保留瞬时反馈）

dblclick:
  wasOut = kind === "out" ;  resetGroup()
  if (pos !== groupStart) { pos = groupStart; sync() }   // ③ 权威回退：回到本组起点
  if (!wasOut) toggleZoomAt(...)                         // ④ 缩回组不再缩放
```

三条要点：

1. **`kind` 只能在新组的第一次点击时设定** —— 第二击不得改写它。否则「放大态双击」的第二击会把 `kind` 从 `out` 改成 `adv`，第 ④ 步又去放大。
2. **第 ③ 步是根治点**：由 `step(-1)`（相对）改为 `pos = groupStart`（绝对）。无论浏览器何时认定双击，回退目标都是同一位置，不再交给运气。
3. **`GROUP_MS` 取 1000ms（长于系统双击窗口上界 900ms）而没有副作用** —— 它只用于「记不记得起点」，不用于「判不判定双击」。没有 `dblclick` 时，起点信息不产生任何效果（第 ③ 步不执行）。这是与旧实现最本质的区别：**窗口错配的后果被限制为「起点被提前重置」，而不是「多切一张」**。

`tapTimer` 整体删除。`step()` 被箭头 / 键盘 / 横滑调用时（非点击路径）须 `resetGroup()`，防止陈旧起点泄漏；`open()` / `close()` 同理。

## 5. 行为对照表

| # | 场景 | 新实现 | 旧实现 |
|---|---|---|---|
| 1 | 1× 快速双击 | 原地 **2.5×** | 原地 2.5× ✅ |
| 2 | 1× 手慢双击（间隔 700ms，系统窗口 900ms） | 原地 **2.5×** | 前进 2 张 + 2.5× ❌ |
| 3 | 1× 两次独立单击（间隔 2s） | 前进 2 张 | 前进 2 张 ✅ |
| 4 | 放大态单击一次 | **缩回 1×，不切图** | 切下一张 + 复位 ❌ |
| 5 | 放大态双击 | **只缩回一次（1×，原地）** | 原地 + 重新放大 2.5× ❌ |
| 6 | 放大态缩回后（>1s）再单击 | 切下一张 | — ✅ |
| 7 | 单击 ×2 间隔 800ms（系统窗口 400ms，浏览器**不**判双击） | 前进 2 张 | 前进 2 张 ✅ |
| 8 | 单击 → 横滑 → 双击 | 原地 2.5× | 原地 2.5× ✅ |
| 9 | 单击 → 方向键 → 双击（<1s 内） | 停在键盘翻页后的位置 + 2.5× | 同 ✅（靠 `resetGroup()`） |
| 10 | 关灯箱再开、再双击 | 正确 | ✅（靠 `open/close` 时 `resetGroup()`） |
| 11 | 放大态拖拽平移后单击 | 被 `didSwipe` 吞掉，需再点一次 | 同（**既有残留，本次不动**） |

场景 2 与 3 的对比是设计核心：**同一段代码，靠「有没有 `dblclick`」区分，而不是靠窗口长度猜。** 场景 7 亦证实 —— 窗口（1000ms）比浏览器窗口（400ms）宽，但没有 `dblclick` 时起点信息不产生效果，故不会误伤。

## 6. 测试方案

TDD：先写测试跑出红灯，再改代码。

| # | 测试 | 修复前 | 断言 |
|---|---|---|---|
| T1 | 放大态单击缩回 | **红**（旧：切了图） | `zoom===1` **且** 照片未变 |
| T2 | 放大态双击只缩回一次 | **红**（旧：zoom=2.5） | `zoom===1` 且照片未变 |
| T3 | 手慢双击不跳两张 | **红**（旧：前进 2 张） | 照片未变 且 `zoom=2.5` |
| T4 | 单击→键盘→双击 | 绿（护栏） | 停在键盘翻页后的位置 |

T1/T2/T3 是「红→绿」证明；T4 是**回归护栏**，专盯 `resetGroup()` 有没有漏（漏了会一次性回退 4 张）。按项目既有做法，护栏不宣称能作红灯证明。

**T3 的实现难点**：`mouse.click` 不产生 `dblclick`（见 §3.1 实测），所以「手慢双击」无法用 Playwright API 复现，只能用 `dispatchEvent` 手工派发事件序列（真实浏览器手慢双击发出的正是这一串）。
